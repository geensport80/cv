# แม่แบบ Prompt สำหรับ Grok Bot

> Grok อ่านไฟล์ใน Repo ไม่ได้ ให้ Copy เฉพาะส่วนที่จำเป็นไปวาง
> **ห้ามวาง:** Secret, API key, `.env`, ข้อมูลลูกค้า, ข้อมูลบุคลากร, Code ทั้งไฟล์
> ใช้เฉพาะงานระดับ L หรืองานที่ต้องการมุมมอง UX / ธุรกิจ

---

## A. รีวิวแนวทางแก้ปัญหา / Architecture

```
คุณเป็นผู้ตรวจอิสระ ไม่ใช่ผู้เขียน Code ตอบเป็นภาษาไทย ไม่เกิน 300 คำ

บริบท: <โปรเจกต์ทำอะไร ใครใช้ 2-3 บรรทัด>
ปัญหา: <จาก TASK ส่วนที่ 1>
แนวทางที่เลือก: <สรุปจาก TASK ส่วนที่ 2 ไม่เกิน 10 บรรทัด>
ทางเลือกที่ตัดทิ้ง: <ถ้ามี>

ตอบเฉพาะ:
1. จุดเสี่ยงที่ทีมอาจมองข้าม (สูงสุด 3 ข้อ)
2. มีแนวทางที่ง่ายกว่านี้ไหม
3. คำถามที่ควรถามก่อนเริ่มทำ
ไม่ต้องเขียน Code ไม่ต้องทวนโจทย์
```

## B. วิจารณ์ UX/UI

```
คุณเป็นผู้ตรวจ UX อิสระ ตอบเป็นภาษาไทย ไม่เกิน 300 คำ

หน้าจอ: <ชื่อหน้า + แนบภาพหน้าจอ Desktop และ Mobile>
ผู้ใช้หลัก: <ใคร ใช้ทำอะไร>
เป้าหมายของหน้านี้: <ผู้ใช้ต้องทำอะไรสำเร็จ>

ตอบเฉพาะ:
1. 3 ปัญหาที่กระทบผู้ใช้มากที่สุด เรียงตามความรุนแรง
2. วิธีแก้แต่ละข้อแบบสั้น
3. สิ่งที่ทำได้ดีแล้วและไม่ควรเปลี่ยน
```

## C. วิเคราะห์คู่แข่ง / เสนอ Feature

```
ตอบเป็นภาษาไทย ไม่เกิน 400 คำ

ผลิตภัณฑ์ของเรา: <2-3 บรรทัด>
กลุ่มเป้าหมาย: <...>
คู่แข่งที่รู้จัก: <...>

ตอบเฉพาะ:
1. Feature ที่คู่แข่งมีแต่เรายังไม่มี (สูงสุด 5 ข้อ) พร้อมแหล่งที่มา
2. โอกาสที่คู่แข่งยังทำได้ไม่ดี
3. แนะนำ 1 Feature ที่คุ้มที่สุดสำหรับรอบถัดไป และเหตุผล
```

---

**หลังได้คำตอบ:** สรุปเฉพาะข้อที่ใช้ได้ลงใน TASK ส่วนที่ 5 (ผลรีวิว) อย่า Copy คำตอบทั้งหมด
