# 02 — Workflow 5 ขั้นตอนแบบประหยัด Token

## ภาพรวม

```
01 PLAN  →  02 BUILD  →  03 TEST  →  04 REVIEW  →  05 APPROVE & MERGE
Claude      ผู้เขียน 1 ตัว   สคริปต์ +       Diff / Grok      ผู้พัฒนา
Code        (Cursor หรือ    Antigravity     เฉพาะประเด็น
            Claude)         เมื่อล้ม
```

ทุกขั้นสื่อสารผ่านไฟล์เดียวคือ `.ai/tasks/TASK-XXX.md` ไม่ใช่การ Copy แชทไปมา

## ขั้นที่ 0 — จัดระดับงาน (ผู้พัฒนาทำ ใช้เวลา 30 วินาที)

| ระดับ | เกณฑ์ | ขั้นที่ใช้ | ผู้เขียน | งบแนะนำ* |
|---|---|---|---|---|
| **S** | 1–3 ไฟล์, ไม่แตะ Logic สำคัญ, ไม่แตะ DB | 02 → 03 → 05 | Cursor Agent | ต่ำ (1 เซสชันสั้น) |
| **M** | 4–10 ไฟล์ หรือแตะ Backend | 01 (สั้น) → 02 → 03 → 04 (Diff) → 05 | ตามตารางบทบาท | กลาง |
| **L** | หลายโมดูล, DB Schema, Security, Auth, การจ่ายเงิน | ครบ 5 ขั้น + Grok | Claude Code | สูง (ต้องอนุมัติก่อน) |

\* ตั้งตัวเลขจริงตามแพ็กเกจที่ใช้ แล้วบันทึกใน `.ai/reports/budget-log.md`

สร้างไฟล์ Task ด้วย:

```bash
./ai-dev-team/scripts/new-task.sh "แก้ปุ่ม Export ไม่ทำงานบน Safari" S
```

## 01 — PLAN (Claude Code) · เฉพาะงาน M และ L

**Input:** คำอธิบายงานใน TASK file
**Output:** ส่วน "แผน" ใน TASK file เท่านั้น ไม่เขียน Code

Prompt ที่ใช้ใน Claude Code:

```
อ่าน .ai/tasks/TASK-XXX.md แล้วกรอกส่วน "แผน" ให้ครบ:
ไฟล์ที่ต้องแก้ (พร้อมเหตุผลบรรทัดเดียว), ขั้นตอน, ความเสี่ยง, เกณฑ์ผ่าน และผู้เขียนที่แนะนำ
ห้ามแก้ Code ในขั้นนี้ อ่านเฉพาะไฟล์ที่จำเป็น
```

**ประหยัด Token:** แผนที่ระบุ "ไฟล์ที่ต้องแก้" ชัดเจนทำให้ผู้เขียนในขั้นถัดไปไม่ต้องค้นทั้ง Codebase ใหม่

## 02 — BUILD (ผู้เขียน 1 ตัว)

**กฎเหล็ก:** ระบุ `ผู้เขียน:` ใน TASK file ก่อนเริ่ม ตัวอื่นห้ามแก้ไฟล์ใน Task นี้

- สร้าง Branch: `task/XXX-ชื่อสั้น`
- แก้เฉพาะไฟล์ในแผน ถ้าต้องแก้ไฟล์นอกแผน ให้เพิ่มลงใน TASK file พร้อมเหตุผล
- เขียน/แก้ Test ของส่วนที่เปลี่ยนไปพร้อมกัน
- จบแล้วกรอกส่วน "ส่งงาน (Handoff)" ใน TASK file

Prompt สำหรับ Cursor Agent:

```
ทำงานตาม .ai/tasks/TASK-XXX.md คุณคือผู้เขียน Code ของ Task นี้
แก้เฉพาะไฟล์ในส่วน "แผน" เสร็จแล้วกรอกส่วน "ส่งงาน" ให้ครบ
```

## 03 — TEST (สคริปต์ก่อน แล้ว Antigravity เมื่อจำเป็น)

1. รัน `./ai-dev-team/scripts/run-checks.sh` (ไม่ใช้ AI ไม่เสีย Token)
2. **ถ้าผ่านหมด** → ข้ามไปขั้น 04 หรือ 05 ทันที
3. **ถ้าล้ม** → ส่งให้ Antigravity เฉพาะไฟล์ `.ai/reports/last-failure.log` ที่สคริปต์ตัดมาให้แล้ว

Prompt สำหรับ Antigravity:

```
อ่าน .ai/tasks/TASK-XXX.md และ .ai/reports/last-failure.log
วิเคราะห์สาเหตุที่ Test/Build ล้ม แล้วกรอกส่วน "ผลทดสอบ" ใน TASK file
ระบุว่าแก้ที่ไฟล์ไหน บรรทัดไหน อย่าแก้ Code เอง ส่งกลับให้ผู้เขียนแก้
```

**เพดาน:** วนแก้ได้ไม่เกิน 2 รอบ ถ้ารอบที่ 3 ยังล้ม ให้หยุดและเปลี่ยนสถานะเป็น `BLOCKED` ให้ผู้พัฒนาตัดสินใจ

## 04 — REVIEW (เฉพาะงาน M และ L)

| สถานการณ์ | ผู้ตรวจ | สิ่งที่ส่งให้ |
|---|---|---|
| Cursor เขียน | Claude Code | `git diff main...HEAD` เท่านั้น |
| Claude Code เขียน | Claude Code **เซสชันใหม่** (`/clear`) หรือ Cursor | Diff เท่านั้น |
| งาน L / UX / ทิศทางธุรกิจ | Grok Bot | สรุปตามแม่แบบ `grok-review-prompt.md` |
| แตะ Auth / ข้อมูลผู้ใช้ / Upload | Claude Code (เซสชันใหม่) ตาม Security Checklist | Diff + รายการ Endpoint |

ผลตรวจกรอกในส่วน "ผลรีวิว" ของ TASK file แบ่งเป็น `ต้องแก้` / `ควรแก้` / `ข้อสังเกต`

ถ้ามี `ต้องแก้` ให้ส่งกลับผู้เขียนเดิม (ไม่ใช่ให้ผู้ตรวจแก้เอง)

## 05 — APPROVE & MERGE (ผู้พัฒนา)

Checklist ก่อน Merge:

- [ ] `run-checks.sh` ผ่าน
- [ ] เปิดหน้าเว็บ/ทดสอบจริงแล้ว (รวม Mobile ถ้าเป็นงาน UI)
- [ ] ไม่มี Secret, `.env`, ข้อมูลบุคคลใน Diff
- [ ] ส่วน "ต้องแก้" ใน Review ปิดหมดแล้ว
- [ ] บันทึก Token/ค่าใช้จ่ายโดยประมาณใน `budget-log.md`
- [ ] เปลี่ยนสถานะ TASK เป็น `DONE`

## สถานะของ Task

```
TODO → PLANNED → IN_PROGRESS → TESTING → IN_REVIEW → DONE
                                   ↓
                                BLOCKED (รอคนตัดสินใจ)
```

## กฎประหยัด Token (ติดไว้ข้างจอ)

1. **เริ่ม Task ใหม่ = เริ่มเซสชันใหม่** (`/clear` ใน Claude Code, New Chat ใน Cursor)
2. **อ้างไฟล์ ไม่ใช่ Copy เนื้อหา** ใช้ `@ไฟล์` แทนการวาง Code ลงแชท
3. **ส่ง Diff ไม่ส่งทั้งไฟล์** ตอนรีวิว
4. **ส่ง Log เฉพาะส่วนที่ล้ม** ไม่ส่ง Log ทั้งหมด
5. **งานเล็กใช้โมเดลเล็ก** เก็บโมเดลแพงไว้สำหรับ PLAN และงาน L
6. **ห้ามถาม AI สองตัวเรื่องเดียวกันพร้อมกัน** เว้นแต่ต้องการความเห็นที่สองโดยตั้งใจ
7. **วนแก้ไม่เกิน 2 รอบ** แล้วให้คนตัดสิน
