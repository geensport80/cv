# 01 — ทบทวนโครงสร้าง AI Development Team v1.0

## สรุปสั้น

โครงสร้างที่ร่างไว้ **ใช้ได้และทิศทางถูก** โดยเฉพาะหลัก "หนึ่ง Task มีผู้เขียน Code คนเดียว" และ "ไม่เรียก AI ทั้ง 4 ตัวทุกครั้ง" ซึ่งเป็นสองเรื่องที่ช่วยประหยัด Token ได้มากที่สุด

แต่มีช่องโหว่ 7 จุดที่ทำให้ยังเปลือง Token และควบคุมงบได้ไม่จริง ด้านล่างคือสิ่งที่ควรคงไว้ สิ่งที่ควรปรับ และเหตุผล

## สิ่งที่ควรคงไว้

| หลักการเดิม | เหตุผลที่ดี |
|---|---|
| Claude Code กับ Cursor Agent ไม่เป็น Lead พร้อมกัน | สองตัวทำงานในเครื่องเดียวกัน (Claude Code รันเป็น Extension ใน Cursor) ถ้าแก้ไฟล์เดียวกันจะชนกันและต้องวิเคราะห์ซ้ำ |
| เลือกตัวทำงานตามขนาดงาน (1–3 ไฟล์ = Cursor) | งานเล็กไม่ต้องจ่ายค่าวิเคราะห์ Codebase ทั้งก้อน |
| Grok เป็น Reviewer ไม่ใช่ผู้เขียน Code | มุมมองอิสระมีค่าที่สุดเมื่อไม่ได้เป็นคนเขียนเอง |
| ผู้พัฒนาเป็นคน Merge | AI ไม่ควรมีสิทธิ์ตัดสินใจขั้นสุดท้าย |

## สิ่งที่ควรปรับ (เรียงตามผลต่อ Token และงบ)

### 1. ไม่มี "ความจำร่วม" ระหว่าง AI → ต้องมีไฟล์ส่งงาน (Handoff) เป็นสัญญากลาง

AI ทั้ง 4 ตัวไม่เห็นแชทของกันและกัน ถ้าไม่มีไฟล์กลาง ทุกตัวจะเริ่มอ่าน Codebase ใหม่เองทุกครั้ง นี่คือแหล่งที่เปลือง Token ซ้ำซ้อนที่ใหญ่ที่สุด

**ปรับ:** ทุก Task มีไฟล์ `.ai/tasks/TASK-XXX.md` ไฟล์เดียว ที่ระบุขอบเขต ไฟล์ที่เกี่ยวข้อง ผู้เขียน และเกณฑ์ผ่าน ตัวถัดไปอ่านแค่ไฟล์นี้กับไฟล์ที่ระบุไว้ ไม่ต้องวิเคราะห์ใหม่

### 2. กฎซ้ำกัน 3 ชุด → ใช้ AGENTS.md เป็นแหล่งความจริงเดียว

ถ้าเขียนกฎแยกใน CLAUDE.md, .cursor/rules และ GEMINI.md นอกจากจะไม่ตรงกันในระยะยาวแล้ว ยังถูกโหลดเข้า Context ทุกครั้งที่เปิดแชท

**ปรับ:** กฎร่วมอยู่ใน `AGENTS.md` ที่เดียว ส่วน `CLAUDE.md` และ `GEMINI.md` แค่ import แล้วเพิ่มเฉพาะบทบาทของตัวเองไม่กี่บรรทัด Cursor อ่าน `AGENTS.md` ได้เองและใช้ `.cursor/rules` เฉพาะกฎที่ผูกกับประเภทไฟล์ (เช่น CSS, PHP)

### 3. ขั้น PLAN บังคับทุกงาน → แยกเส้นทางตามขนาดงาน

ถ้าทุกงานต้องผ่าน Claude Code วางแผนก่อน การแก้ CSS บรรทัดเดียวก็จะเสียค่า Plan ฟรี ๆ

**ปรับ:** แบ่งงานเป็น 3 ระดับ (ดู [02-workflow.md](02-workflow.md))
- **S (เล็ก):** BUILD → TEST → MERGE (ข้าม PLAN และ REVIEW)
- **M (กลาง):** PLAN สั้น → BUILD → TEST → REVIEW Diff → MERGE
- **L (ใหญ่/เสี่ยง):** ครบ 5 ขั้น และ Grok ตรวจเฉพาะประเด็น

### 4. ให้ AI "รัน Test" เปลือง Token โดยไม่จำเป็น

การรัน `npm test` หรือ `phpunit` ไม่ต้องใช้ AI คิด ถ้าให้ Antigravity รันแล้วอ่าน Log ทั้งหมด จะเสีย Token กับ Output ที่ผ่านแล้ว

**ปรับ:** ใช้สคริปต์รัน Test/Build ก่อน (ฟรี) แล้วส่งให้ Antigravity **เฉพาะผลที่ล้มเหลว** เพื่อวิเคราะห์สาเหตุ ถ้าผ่านหมดไม่ต้องเรียก AI เลย

### 5. Claude Code ตรวจ Security ของ Code ที่ตัวเองเขียน

ในตาราง PHP/Backend มี Claude Code เป็นตัวหลัก และ Code Security Review ก็เป็น Claude Code อีก เท่ากับตรวจงานตัวเอง ซึ่งมักมองไม่เห็นจุดบอดเดิม

**ปรับ:** ถ้า Claude Code เป็นผู้เขียน ให้ตรวจ Security ด้วย **เซสชันใหม่ที่เห็นแค่ Diff** (ไม่มีบริบทการเขียน) หรือให้ Antigravity/Cursor เป็นผู้ตรวจแทน

### 6. ไม่มีเพดานงบและจุดหยุด

โครงสร้างบอกว่าใครทำอะไร แต่ไม่บอกว่าเมื่อไรต้องหยุด วงจร "แก้ → Test ไม่ผ่าน → แก้ใหม่" ที่ไม่มีเพดานคือจุดที่งบบานปลาย

**ปรับ:** กำหนดกฎ
- แก้ซ้ำได้ไม่เกิน 2 รอบต่อ Task ถ้ายังไม่ผ่านให้หยุดและส่งกลับคนตัดสินใจ
- ตั้งงบต่อ Task ตามขนาด (S/M/L) และบันทึกใน `.ai/reports/budget-log.md`
- ใช้โมเดลถูกกว่ากับงานเล็ก และล้างบริบท (`/clear`) เมื่อเริ่ม Task ใหม่

### 7. Grok เข้าถึง Repo ไม่ได้ และอาจเห็นข้อมูลที่ไม่ควรเห็น

Grok ไม่อ่านไฟล์ในเครื่องได้ ต้อง Copy เนื้อหาไปวาง ถ้าวาง Code ทั้งไฟล์จะเปลือง และเสี่ยงหลุดข้อมูลลับหรือข้อมูลบุคคล

**ปรับ:** ส่งให้ Grok เฉพาะ "สรุปการเปลี่ยนแปลง + คำถามที่ต้องการคำตอบ" ตามแม่แบบ `.ai/reviews/grok-review-prompt.md` และห้ามส่ง Secret, ข้อมูลลูกค้า หรือข้อมูลบุคลากร

## ตารางบทบาทฉบับปรับปรุง

| งาน | ตัวหลัก | ตัวตรวจสอบ | หมายเหตุที่เปลี่ยน |
|---|---|---|---|
| วิเคราะห์ Requirement | Claude Code | Grok Bot (เฉพาะงาน L) | Grok ไม่ต้องตรวจงาน S/M |
| System Architecture | Claude Code | Grok Bot | — |
| WordPress Theme (template, CSS) | Cursor Agent | Claude Code (ดู Diff) | — |
| WordPress Theme (functions.php, hooks, query) | Claude Code | Cursor Agent | **ใหม่:** ส่วน PHP ของ Theme ไปทาง Backend |
| Frontend / UI | Cursor Agent | Claude Code (ดู Diff) | — |
| PHP / Backend | Claude Code | Cursor Agent | — |
| Database Design | Claude Code | Antigravity | — |
| Refactor หลายไฟล์ | Claude Code | Cursor Agent | — |
| Unit / Integration Tests (เขียน Test) | ผู้เขียน Code ของ Task นั้น | Antigravity | **เปลี่ยน:** คนเขียน Code เขียน Test ไปพร้อมกัน ไม่ต้องให้อีกตัวอ่าน Code ใหม่ |
| รัน Test / Build | สคริปต์ (ไม่ใช้ AI) | Antigravity (เฉพาะเมื่อล้ม) | **เปลี่ยน:** ประหยัด Token มาก |
| Build / Debug | Antigravity CLI | Cursor Agent | — |
| Market Research | Grok Bot | Claude Code | — |
| Code Security Review | Claude Code **เซสชันใหม่** หรือ Antigravity | ผู้พัฒนา | **เปลี่ยน:** ไม่ตรวจงานตัวเองในเซสชันเดียวกัน |

## ข้อควรระวังเรื่องเครื่องมือ

- **Claude Code ใน Cursor** กับ **Cursor Agent** ใช้ Working Tree เดียวกัน ห้ามให้ทั้งสองแก้ไฟล์พร้อมกัน ถ้าจำเป็นต้องทำงานคู่ขนาน ให้ใช้ `git worktree` แยกโฟลเดอร์
- ชื่อไฟล์กฎที่เครื่องมือแต่ละตัวอ่าน (เช่น `AGENTS.md`, `GEMINI.md`) อาจเปลี่ยนตามเวอร์ชัน ให้ตรวจเอกสารของเวอร์ชันที่ใช้อยู่ก่อนติดตั้ง
